Engenharia de requisitos

Uma abordagem sistemática e documentada para a especificação e gerenciamento de requisitos

Requisitos
	uma condição ou capacidade necessárias para um usuário resolver um problema ou alcançar um objetivo.

Stakeholder
	é uma pessoa ou organização que possui uma influência direta ou indireta com os requisitos do sistema

Objetivos
	Conhecer os requisitos, documentar, gerenciar, minimizar os requisitos, etc.

Característica
	Porta de entrada do desenvolvimento do software
	É a primeira e mais crítica fase do ciclo de vida do software
	Base para todas as outras disciplinas
	A ER não é uma etapa isolada

Importância
	Corrigir um requisito erro em produção pode custar 200x mais caro

Relação com o ciclo de vida
	Seja cascata, incremental, iterativo ou ágil, a ER sempre aparece

Conexão entre qualidade de software
	Qualidade externa
	Normas conectam atributos de qualidade e requisitos
	SWEBOK coloca a ER como pilar essencial de todas as áreas

Elicitação
	É  a arte e a ciência de descobrir, entender e extrair a necessidade dos stakeholders.
	Vai além de apenas perguntar  que eles querem, envolve técnicas para desvendar os requisitos

Documentação
	É o processo de registrar os requisitos de forma clara, precisa e organizada
	Transforma as informações coletadas em artefatos formais que servem como contrato e guia para o desenvolvimento
	É a fase de "escrever" o que foi descoberto.
	Diversas técnicas são utilizadas para documentar os requisitos, seja por meio da linguagem natural ou modelos linguísticos

Validação ou Negociação
	É a atividade de garantir os requisitos estão corretos, completos, consistentes e viáveis

Gerenciamento
	Trata de acompanhar e controlar mudanças nos requisitos a longo do ciclo de vida do projeto
	É a fase de manter o controle

Restrições
	Fortemente influenciada por restrições de projeto, que determinam como as atividades serão conduzidas
	Fatores como o perfil e a disponibilidade das pessoas envolvidas, as características do domínio de aplicação e as limitações organizacionais

Elicitação de Requisitos
	Uma atividade central de ER é a elicitação de requisitos para o sistema a ser desenvolvido.
	A base para elicitação de requisitos é formada pelo conhecimento sobre o contexto do sistema a ser desenvolvido obtido durante a ER, que inclui as fontes de requisitos a serem analisadas e investigadas
	Conceito
		É a primeira atividade prática
	Natureza iterativa
		Raramente a elicitação é um processo linear
	Desafios
		Ambiguidade, inconsistência, conhecimento implícito, mudança
	Objetivos
		Captar necessidades reais dos usuários
		Compreender domínio do problema
		Definir escopo
		Alinhar expectativas
